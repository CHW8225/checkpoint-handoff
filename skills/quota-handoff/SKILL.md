# 额度交接与恢复

在账户短周期额度剩余 **≤8%** 时，优先保存可恢复的工作状态；额度刷新后，核验条件再继续原任务。称呼用户为“前行者”，默认中文沟通。

## 能力与触发

- skill 是执行规则，不是常驻监控进程。只有已加载本 skill 的运行中聊天，才能按下列时机检查额度；安装不等于所有聊天都已启用。
- 用户请求本流程，即授权为当前未完成任务登记恢复唤醒；不授权新任务、其他聊天、权限提升或额外对外操作。
- 开始任务、每个主要步骤结束、准备昂贵操作之前，读取一次额度。持续工作时，距上次检查满 5 分钟，在下一工具边界再查；不是硬实时的 8% 拦截，单次长调用可能跨过阈值。
- 每个主要步骤维护简短进度，防止单次调用直接耗尽额度而来不及交接。

## 读取与判断

发现并调用原生 `get_usage_limits` 工具（本环境为 `mcp__codex_app__get_usage_limits`）。不要读取认证文件或使用 API token 猜测订阅额度。

1. 优先 `rateLimitsByLimitId`，选择明确适用于当前模型的 bucket；只有缺少多 bucket 视图时才用 `rateLimits`。无法确认适用 bucket 时说明不确定性，不默认取列表第一项。
2. `usedPercent` 是已用比例。用代码算 `remaining = Math.max(0, Math.min(100, 100 - usedPercent))`，但先验证它是有限数值。`null`、缺失或读失败表示未知，不能算作剩余 100%。
3. 读取 `windowDurationMins`，按实际短周期窗口处理。用户口中的“每小时额度”不意味着每整点刷新；300 分钟窗口应说明为 5 小时。不要把上下文剩余、目标 token budget 当成账户额度。
4. 记录 `resetsAt`（Unix 秒）、观测时间、bucket、窗口长度和剩余比例。转换时间用日期库并标明时区，默认 Asia/Shanghai。明显过期或矛盾的数据应重新读取一次；仍异常则记为未知。

| 观测条件 | 动作 |
| --- | --- |
| 短周期剩余 >8%，普通额度可用 | 继续原任务 |
| 短周期剩余 ≤8%，或普通额度不可用 | 保存交接，停止新增长步骤 |
| 周额度已耗尽、其他适用限制生效 | 保存交接，等待该限制解除 |
| 额度信息未知 | 保存已有进度，说明无法保证阈值触发；不宣称已监控或已恢复 |

## 保存交接

先完成正在写入操作的最小安全收尾，不趁最后额度启动新分析或大批工具调用。

在当前项目写入 `.codex-handoffs/<thread-id>/handoff.md`，使用 [handoff-template.md](handoff-template.md)。没有可靠 thread id 时使用当前聊天专属的时间戳路径，并记录无法自动定位聊天。不要用其他最近聊天代替。已有用户内容应保留，更新本流程自己管理的状态即可。

至少记录：原始目标与完成标准、授权范围、已完成项及验证证据、文件绝对路径、未完成项、精确下一步、正在执行或结果未知的操作、额度快照、恢复条件、自动化 id/失败原因。只保存任务所需信息，不复制整段会话或凭据。

写完回读，确认文件存在且下一步可执行。只有完成并核验交接文件，才报告“已交接”。用 `waiting_quota` 表示任务本地状态；不要因此擅自调用 goal 工具把系统目标标为 paused 或 complete。

## 登记恢复唤醒

优先发现 `automation_update`，按其**当前工具描述和 schema**为当前聊天创建或更新 heartbeat。不要为每次检查新建一个自动化，也不要用独立 cron 聊天替代原聊天。

- 先检查本交接记录的 automation id 及已有匹配自动化，复用同任务记录。
- 已知重置时间时，让第一次唤醒在受阻窗口 `resetsAt` 后约 60 秒；多个窗口受阻时，初始候选时间取受阻窗口重置时间的最大值，到时仍须重新核验。仅 8% 保护触发时等短周期重置。
- 若当前 heartbeat 仅支持循环检查，选择工具支持的低频周期（通常 30 分钟），提示词写明 `not_before`，到点前只核验状态，不开展任务；不承诺精确到秒。
- 提示词包含交接文件绝对路径、原任务、8% 阈值、not_before、恢复条件，以及完成/用户取消后停用本恢复自动化的要求。状态无变化时保持安静，只在恢复、完成、失败或需要用户行动时通知。
- 工具返回成功且有可验证记录后，将 automation id、实际计划、目标聊天写回交接文件，再报告已登记。返回结果不明确时先查询，不重复创建。
- 无调度工具、无法定位原聊天、没有可信重置时间且无法安排低频检查，或登记被拒绝：保留交接，明确“自动恢复未启用”，提供手动恢复提示词。不要用长时间 sleep、循环模型调用或安装未知守护程序冒充后台恢复。

heartbeat 提示词示例：

> 为本聊天原任务检查额度恢复。先读取交接文件的绝对路径及最新用户指令；用户已停止、任务已完成或转为等待审批时，停用本恢复自动化。not_before 前不开展任务。重新调用 get_usage_limits，确认适用短周期剩余 >8%、所有适用窗口可用且普通额度允许；满足后从交接文件的下一步继续，不重复已完成或结果未知的外部操作。其余情况更新等待原因，等待下一次低频检查。仅在恢复、完成、失败或需要用户行动时通知。

## 刷新后继续

1. 读取交接及最新用户指令；用户取消、改变目标、等待输入/审批，优先遵从。恢复授权仅覆盖原未完成任务，完成后结束。
2. **重新获取**额度：时间到了不等于额度可用。短周期剩余必须 >8%，`ordinaryUsageAllowed`（若返回）必须为 true，周额度及其他适用限制均应允许工作。未知时继续等待或报告阻塞。
3. 核对文件、分支和在途操作。外部上传/发布/付款等结果未知时，先查实际状态，不能直接重放；保持原审批、安全和预算边界。
4. 将交接改为 `running`，从精确下一步开始。只在原聊天当前唤醒回合内恢复，不另启 CLI、子代理或其他聊天执行同一交接。已有正在运行的恢复回合或已处理的交接批次时，不再发送重复继续指令；若发现并行写入或执行归属不明，停止自动恢复并报告，不能抢占。不用 `send_message_to_thread` 给自己递归发“继续”。
5. 再次触及 ≤8% 时更新同一交接和自动化；原任务完成或用户取消后，将交接改为 `complete`/`cancelled`，停用本流程登记的自动化并核验结果。

手动恢复提示词：`使用 $quota-handoff，先读取 <交接文件绝对路径>，核验最新额度和用户指令，再从下一步继续原任务。`

原理与已有方案见 [references/sources.md](references/sources.md)。未做真实跨额度窗口测试时，应明确说明，不能声称无人值守续跑已验证。
